pydanic配合json序列化

CustomEncoder 与 json.dumps 的协作机制说明文档

一、背景与问题说明

在实际工程中，直接使用 json.dumps() 序列化复杂对象（如 Pydantic 对象、HTTP Header、流式对象等）往往会失败。失败原因在于：这些对象并非 JSON 原生支持的类型。

为解决该问题，引入了一个 自定义 JSONEncoder（CustomEncoder），用于在序列化过程中对“问题对象”进行兜底处理。

class CustomEncoder(json.JSONEncoder):
    """
    直接dump pydantic 对象存在问题，这里加一个 hack
    """

    def default(self, obj):
        """json dump default"""
        if obj.__class__.__name__ == "SerializationIterator":
            return None

        if obj.__class__.__name__ == "CaseInsensitiveDict":
            return dict(obj)

        if isinstance(obj, StreamingValue):
            return ""

        return super().default(obj)

该类的核心在于 重写 JSONEncoder.default() 方法。

三、json.dumps(…, cls=CustomEncoder) 的工作机制

1. 本质行为

当调用：

1
2


json.dumps(last_item, cls=CustomEncoder)

内部逻辑等价于（简化后）：

1
2
3


encoder = CustomEncoder()
encoder.encode(last_item)

2. JSON 原生支持的类型

以下类型在序列化时**不会调用 **default()：

  • dict
  • list / tuple
  • str
  • int / float
  • bool
  • None

3. default() 的调用规则（一句话版）

当 json.dumps 在递归遍历对象树时，遇到一个 JSON 原生不支持的对象，就会调用 default(obj)。 注意：

  • default()不是只调用一次
  • 它会在 每一个不支持的节点 上被触发

四、CustomEncoder.default 的处理逻辑详解

1️⃣ SerializationIterator（Pydantic 内部对象） 

1
2


if obj.__class__.__name__ == "SerializationIterator":    returnNone

常见来源：

  • Pydantic v2
  • FastAPI Response
  • model_dump() 内部流式序列化

处理策略：

  • 直接丢弃
  • JSON 中表现为 null

2️⃣ CaseInsensitiveDict（HTTP Header） 

1
2


if obj.__class__.__name__ == "CaseInsensitiveDict":    returndict(obj)

常见来源：

  • requests.Response.headers
  • HTTP 请求 / 响应头

处理策略：

  • 显式转换为普通 dict
  • 保留全部键值信息

3️⃣ StreamingValue（流式对象） 

1
2


ifisinstance(obj, StreamingValue):    return""

常见来源：

  • LLM streaming
  • SSE / chunked response
  • 延迟计算对象

处理策略：

  • 不序列化内容
  • 返回空字符串，避免阻塞或异常

4️⃣ 兜底失败（保持严格） 

1
2


returnsuper().default(obj)

行为：

  • 抛出 TypeError: not JSON serializable

设计意义：

  • 只对“已知问题对象”做 hack
  • 避免悄悄吞掉真正的错误类型

八、工程视角总结（一句话）

CustomEncoder 是一个“best-effort JSON 序列化适配器”，通过在递归过程中拦截不可序列化对象，将其压平为安全的 JSON 原生值，从而保证 json.dumps 在复杂对象场景下不崩溃。

九、适用场景

  • 日志系统（request / response dump）
  • 审计记录
  • Debug 快照
  • LLM 中间态保存
  • FastAPI / Pydantic 对象持久化
