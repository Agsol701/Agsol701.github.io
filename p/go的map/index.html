go的map

Oct 06, 2025

Go 语言 中 map 是一个 key（索引）和 value（值）形式的无序的集合，也可以称为关联数组或字典，Golang 中的 map 能够快速根据给定 key，找到对应的 value 的数据结构。 Golang 的 map 的 key 可以是任何可以使用 == 进行比较的 数据类型，比如 int、string、bool 等，value 可以是任意的类型。 map 是一个无序的数据结构，因此同一个 map，每次遍历获取的顺序很可能是不一致的。

Go语言map定义

语法 

1

var mapName map[keyType]valueType

参数

参数 描述
var 声明变量使用的关键字。
mapName 声明的 map 变量的变量名。
map 声明 map 变量的关键字。
keyType map 的键的类型。
valueType map 的值的类型。

说明

声明一个 变量 名为 mapName， key 为 keyType 类型，value 为 valueType 类型的 map。

package main

import (
	"fmt"
	"reflect"
	"strings"
)

func main() {
	fmt.Println(strings.Repeat(">", 20))
	map1 := map[string]string{
		"cat":   "tom",
		"mouse": "jerry",
		"dog":   "spike",
	}
	map2 := make(map[string]string, 5)
	map2["name"] = "tom"
	map2["age"] = "18"
	map2["gender"] = "male"
	map3 := make(map[string]string, 1)
	map3["name"] = "jerry"
	map3["age"] = "18"
	map3["gender"] = "male"
	fmt.Println("map1", map1, reflect.TypeOf(map1), len(map1))
	fmt.Println("map2", map2, reflect.TypeOf(map2), len(map2))
	fmt.Println("map3", map3, reflect.TypeOf(map3), len(map3))
}

map的遍历

Go 语言 中 map 的遍历只能使用 for range 的形式，for range 循环返回的第一个是 map 的 key，返回的第二个是 map 的 value。 使用 for range 遍历 map，如果我们只使用一个返回参数接受，那么返回的是 map 的 key。因此 map 是无序的，因此同一个 map，每次遍历获取的结果的顺序很可能是不一致的。

package main

import (
	"fmt"
	"math/rand"
	"sort"
	"strings"
	"time"
)

func main() {
	fmt.Println(strings.Repeat(">", 20))
	//本质是通过取出 key，排序后按照key取出value
	rand.Seed(time.Now().UnixNano()) //初始化随机数种子
	var scoreMap = make(map[string]int, 200)
	for i := 0; i < 100; i++ {
		key := fmt.Sprintf("stu%02d", i) //生成stu开头的字符串
		value := rand.Intn(100)          //生成0~99的随机整数
		scoreMap[key] = value
	}
	//取出map中的所有key存入切片keys
	var keys = make([]string, 0, 200)
	for key := range scoreMap {
		keys = append(keys, key)
	}
	//对切片进行排序
	sort.Strings(keys)
	//按照排序后的key遍历map
	for _, key := range keys {
		fmt.Println(key, scoreMap[key])
	}
}

syncMap

sync.Map 是并发写安全的 Go 语言 sync.Map 无须初始化，直接声明即可使用。 sync.Map 不能使用 map 的方式进行取值和设置等操作，而是使用 sync.Map 的方法进行调用，Store 表示存储，Load 表示获取，Delete 表示删除。 使用 Range 配合一个回调函数进行遍历操作，通过回调函数返回内部遍历出来的值，Range 参数中回调函数的返回值在需要继续迭代遍历时，返回 true ，终止迭代遍历时，返回 false。 Go 语言 中 sync.Map 的 LoadOrStore 函数 表示，如果我们获取的 key 存在，那么就返回 key 对应的元素，如果获取的 key 不存在，那么就返回我们设置的值，并且将我们设置的值，存入 map。

package main

import (
	"fmt"
	"reflect"
	"strings"
	"sync"
)

// myRangeTrue 遍历 sync.Map 中的键值对，始终返回 true 以继续遍历
func myRangeTrue(key, value interface{}) bool {
	fmt.Printf("myRangeTrue: key=%v, value=%v\n", key, value)
	return true
}

// myRangeFalse 遍历 sync.Map 中的键值对，始终返回 false 以停止遍历
func myRangeFalse(key, value interface{}) bool {
	fmt.Printf("myRangeFalse: key=%v, value=%v\n", key, value)
	return false
}

func main() {
	fmt.Println(strings.Repeat(">", 20))
	var m1 sync.Map
	// 添加元素Store
	m1.Store("name", "tom")
	m1.Store("age", 18)
	m1.Store("hoppy", []string{"mouse", "duck", "agsol"})
	m1.Store("gender", "male")
	fmt.Println(strings.Repeat("~", 20))
	fmt.Println("m1 value:", m1)
	fmt.Println("m1 type:", reflect.TypeOf(m1))
	// 取元素Load
	// Load不存在的key也不会报错
	hoppy, err1 := m1.Load("hoppy")
	duck, err2 := m1.Load("duck")
	fmt.Println(strings.Repeat("~", 20))
	fmt.Println("m1 hoppy:", hoppy, err1)
	fmt.Println("m1 duck:", duck, err2)
	// 删除元素Delete
	// 使用 sync.Map Delete 删除不存在的元素，不会报错
	m1.Delete("name")
	m1.Delete("xxxx")
	fmt.Println(strings.Repeat("~", 20))
	fmt.Println("m1 value:", m1)
	// 遍历Range sync.Map 的 Range 顺序完全不可预测。
	// 返回的 bool 结果，如果为 true，表明遍历继续，false，表明遍历结束。
	m1.Range(myRangeTrue)
	m1.Range(myRangeFalse)
	// LoadOrStore
	// key存在，就取值；key不存在，就设置key=value=args
	m1.LoadOrStore("age", 20)
	fmt.Println(strings.Repeat("~", 20))
	m1.Range(myRangeTrue)
	m1.LoadOrStore("addr", "shanghai")
	fmt.Println(strings.Repeat("~", 20))
	m1.Range(myRangeTrue)
}

使用make和不使用make

在 Golang 中，使用 make 函数和不使用 make 创建 map 有一些区别。以下是它们的主要区别：

  1. 使用 make 创建 map： 
    1

    m := make(map[string]int)
    • make 函数用于创建 map，用于初始化一个空的 map，并分配了足够的内存空间来存储一定数量的元素。这可以提高性能，特别是在大型 map 的情况下。
    • 使用 make 创建 map 同时进行了内存分配，因此 map 可以立即用于存储键值对。
  2. 不使用 make 创建 map： 
    1

    m := map[string]int{}
    或者 
    1

    var m map[string]int
    • 不使用 make 也可以创建一个空的 map，但不会分配内存空间。这样的 map 在第一次使用时会动态地分配所需的内存。这可能会导致在添加大量元素时发生多次重新分配，影响性能。
    • 如果 map 预计会存储大量的键值对，最好使用 make 预先分配足够的内存。
总结

总的来说，使用 make 可以在创建 map 时提供更好的性能，特别是在知道大致存储量的情况下。不使用 make 可以节省一些代码，但可能会在运行时导致多次动态分配内存。 在实践中，如果你事先知道 map 的大致大小，且希望提高性能，建议使用 make。如果不确定大小或者大小可能变化，你仍然可以不使用 make，因为 Go 的运行时系统会在需要时进行内存分配。
