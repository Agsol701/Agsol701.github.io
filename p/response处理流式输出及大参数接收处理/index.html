处理流式输出中，response.text和response.content的区别

在处理流式输出（如 SSE 服务器推送、大文件下载、分块传输等场景）时，response.text 和 response.content 的区别主要体现在数据形式、处理方式和适用场景上，核心差异源于流式传输的 “分块” 特性。以下是详细对比：

1. 数据形式与处理逻辑

特性 response.text response.content
数据类型 字符串（str） 字节流（bytes）
处理逻辑 会等待所有数据接收完成后，将完整字节流按编码（如 utf-8）解码为字符串。 直接返回接收到的原始字节片段，不等待完整数据，也不做解码。
流式适配性 不适合流式处理：必须等全量数据加载到内存后才能获取，无法逐块处理。 适合流式处理：可实时获取分块字节数据，边接收边处理。

2. 流式场景下的核心区别

在流式输出中（通常通过 stream=True 启用，如 requests.get(url, stream=True)），服务器会将数据分块传输，而非一次性返回完整内容。此时两者的行为差异显著：

（1）response.text 的问题：无法实时处理

response.text 的设计是获取完整响应的文本内容，其内部逻辑是：

  • 等待所有分块数据传输完成，拼接成完整字节流；
  • 根据响应头的编码（如 Content-Type: text/html; charset=utf-8）解码为字符串。

在流式场景中使用 response.text 会导致：

  • 阻塞等待：必须等到所有数据传输完毕才能拿到结果，失去 “流式” 的实时性；
  • 内存爆炸：若数据量极大（如 GB 级日志流），完整加载到内存会导致 OOM（内存溢出）。

示例（错误用法）：

import requests

# 启用流式传输
response = requests.get("https://api.example.com/stream", stream=True)
# 错误：response.text 会等待所有数据接收完成才返回
content = response.text  # 大流式数据会导致内存飙升、长时间阻塞

（2）response.content 的特点：支持逐块处理

response.content 本质是原始字节数据的容器，在流式场景中：

  • 不会等待全量数据，而是随着分块传输实时更新；
  • 可通过迭代器（如 response.iter_content() 或 response.iter_lines()）逐块获取字节数据，边接收边处理。

这完全适配流式场景的需求（实时性、低内存占用）。

示例（正确用法）：

import requests

response = requests.get("https://api.example.com/stream", stream=True)
# 逐块读取字节数据（每块 1024 字节）
for chunk in response.iter_content(chunk_size=1024):
    if chunk:  # 过滤空块
        # 处理当前字节块（如写入文件、解析实时数据）
        process_chunk(chunk)  # 自定义处理函数

3. 流式场景的适用选择

场景 推荐使用 原因
SSE 服务器推送 response.content 分块处理 需实时解析每一条推送的事件（如 data: ... 行），text 无法逐块解码。
大文件下载 response.content 分块写入 边接收边写入磁盘，避免占用大量内存。
实时日志流处理 response.content 分块解析 实时提取日志中的关键信息，无需等待完整日志。
非流式的小文本响应 response.text 便捷获取解码后的字符串，适合一次性处理的场景。

4. 流式处理中解码的正确方式

若流式传输的是文本数据（如 JSON 流、SSE 事件），需要将字节块解码为字符串，但**不能用 **response.text，而是应在分块处理时手动解码：

示例（流式文本解码）：

import requests

response = requests.get("https://api.example.com/text-stream", stream=True)
for chunk in response.iter_content(chunk_size=1024, decode_unicode=False):
    if chunk:
        # 手动指定编码解码当前块（如 utf-8）
        text_chunk = chunk.decode("utf-8")
        print(f"实时处理：{text_chunk}")
  • 关键：decode_unicode=False 确保获取原始字节，再按实际编码手动解码（避免默认编码错误）。

总结

在流式输出场景中：

  • response.content** 是唯一选择**：支持分块读取、实时处理，内存友好，适配流式传输的本质；
  • response.text** 不适用**：会等待全量数据、占用大量内存，失去流式处理的意义。

核心差异可概括为：content 面向 “字节流的分块实时处理”，text 面向 “完整文本的一次性获取”。

def chunk_iter_lines(resp, chunk_size=65536, decode_unicode=False, encoding=None, trim_threshold=1 << 20):
    """
    高性能 iter_lines 实现，优化超长行场景。
    Args:
        resp: requests.Response (需 stream=True)
        chunk_size: 每次读取块大小 (默认 64KB)
        decode_unicode: 是否解码为 str
        encoding: 解码使用的编码 (默认 resp.encoding or utf-8)
        trim_threshold: 缓冲区超过该值时清理前缀 (默认 1MB)
    """
    buf = bytearray()
    start = 0
    read = resp.raw.read
    enc = encoding or getattr(resp, "encoding", None) or "utf-8"

    while True:
        chunk = read(chunk_size)
        if not chunk:
            break
        buf.extend(chunk)

        while True:
            nl = buf.find(b'\n', start)
            cr = buf.find(b'\r', start)

            if nl == -1 and cr == -1:
                break

            # CR 在缓冲末尾，可能是 CRLF 跨块，等待下一次 read
            if cr != -1 and cr == len(buf) - 1 and (nl == -1 or cr < nl):
                break

            if nl == -1:
                line_end = cr
                line_ending_len = 1
            elif cr == -1:
                line_end = nl
                line_ending_len = 1
            else:
                if cr < nl and cr + 1 < len(buf) and buf[cr + 1] == 10:
                    line_end = cr
                    line_ending_len = 2
                else:
                    line_end = min(cr, nl)
                    line_ending_len = 1

            line = bytes(buf[start:line_end])
            start = line_end + line_ending_len

            if decode_unicode:
                yield line.decode(enc, errors="replace")
            else:
                yield line

        # 缓冲区定期修剪，避免无限增长
        if start > trim_threshold:
            del buf[:start]
            start = 0

    if start < len(buf):
        leftover = bytes(buf[start:])
        if decode_unicode:
            yield leftover.decode(enc, errors="replace")
        else:
            yield leftover
