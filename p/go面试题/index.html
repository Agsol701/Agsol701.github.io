值接收者和指针接受着的区别

值接收器使用的是传入参数的副本,更改副本不影响传入参数本身的数据

指针接收器接收参数的指针,直接改变参数本身的数据

什么时候使用指针接收器

  1. 需要更改接收器中参数的值的时候
  2. 当作为参数的结构体的体积很大的时候
  3. 保证数据一致性

函数返回局部变量的指针是否安全

安全,但不建议使用

Go编译器会分析函数返回值,如果局部变量的作用域超出该函数发生逃逸,Go编译器就会将该变量放到堆上

内存栈区:连续分配,存放函数名参数返回值等信息

内存堆区:离散分配,存放程序员自定义的数据

可以在变异的时候添加go run -gcflags="-m -m -l" main.go来查看变量逃逸的情况

函数的参数是值传递还是引用传递

golang中函数的传递的都是参数的副本

值传递就传递值的副本

引用传递传递的就是地址的副本

Int,float,bool,string,数组,struct默认传递值

指针类型,slice,map,channel,interface默认传递引用

Slice底层结构

底层数组指针+长度(len)+容量(cap)

Slice深拷贝和浅拷贝

深拷贝

拷贝数据本身,创建一个新的对象,新对象与原对象不共享内存

方法:copy(dst[], src[])

浅拷贝

拷贝的数据的地址,只复制指向地址的指针,新对象至改变也会影响原数据

Slice的扩容机制

  • 如果新申请容量(cap)大于2倍旧容量(old.cap),最终容量(newcap)就是新申请的容量
  • 如果旧切片的长度小于1024,则最终容量(newcap)就是旧容量(old.cap)的两倍
  • 如果旧切片的长度大于等于1024,则最终容量(newcap)从旧容量(old.cap)开始每次增加$\frac{1}{4}$,直到最终容量(newcap)大于等于新申请的容量(cap)
  • 如果最终容量(cap)计算值溢出,则最终容量(cap)就是新申请的容量(cap)

线程安全

多个线程对同一个对象执行写操作的时候,不会导致数据丢失,就是线程安全的.

  2. 读写锁
  3. 原子操作
  4. sync.once

// A header for a Go map.
type hmap struct {
count     int		// 代表哈希表中的元素个数，调用len(map)时，返回的就是该字段值。
flags     uint8		// 状态标志（是否处于正在写入的状态等）
B         uint8		// buckets（桶）的对数
// 如果B=5，则buckets数组的长度 = 2^B=32，意味着有32个桶
noverflow uint16		// 溢出桶的数量
hash0     uint32		// 生成hash的随机数种子
buckets   unsafe.Pointer		// 指向buckets数组的指针，数组大小为2^B，如果元素个数为0，它为nil。
oldbuckets unsafe.Pointer		// 如果发生扩容，oldbuckets是指向老的buckets数组的指针，老的buckets数组大小是新的buckets的1/2;非扩容状态下，它为nil。
nevacuate  uintptr		// 表示扩容进度，小于此地址的buckets代表已搬迁完成。
extra *mapextra		// 存储溢出桶，这个字段是为了优化GC扫描而设计的，下面详细介绍
}

bmap结构体

bmap 就是我们常说的“桶”，一个桶里面会最多装 8 个 key，这些 key 之所以会落入同一个桶，是因为它们经过哈希计算后，哈希结果的低B位是相同的，关于key的定位我们在map的查询中详细说明。在桶内，又会根据 key 计算出来的 hash 值的高 8 位来决定 key 到底落入桶内的哪个位置（一个桶内最多有8个位置)。
go中key和value是分开存储的

存储形式是[k1,k2,k3,,,],[v1,v2,v3,,,]

取值的时候根据再将k,v对应起来

而不是{k1:v1,k2:v2,,,}的形式,能更好的利用内存空间

map的遍历为什么无序

  1. map的遍历不是从0号开始的,而是从一个随机的bucket开始的
  2. map发生扩容后,key会迁移,也会导致两次遍历的结果不一致

map为什么是非线程安全的

map默认并发不安全,同时对map进行并发读写会panic.

go为了保证性能,自己没有给map加锁

实现map线程安全的方法
  1. 使用读写锁sync.RWMutex
  2. 使用go提供的sync.Map

map冲突解决方式

Python的dict使用的是开放寻址法

Go的map用的是链地址法

import "sync"

var (
    m sync.Mutex
    wg sync.WaitGroup		//等待组
    x int
)

func add(){
    for i:=0;i<50000;i++{
        m.Lock()		//获取互斥锁
        x += 1
        m.Unlock()	//释放互斥锁
    }
    wg.Done()
}

func main(){
    wg.Add(2)		//设置两个goroutine

    go add()
    go add()

    wg.wait()
    fmt.Println(x)
}

go互斥锁的实现

首先会进入公平模式,当一个goroutine获得锁后,其他的goroutine会进入自旋状态(不进入阻塞队列,而是轮询cpu,直到获得资源);在自旋4次之后,就会将这个goroutine放入阻塞队列.

当goroutine等待锁的时间超过1ms时,就会进入饥饿状态,这时候会直接把锁给队列中的第一个goroutine,后面进来的新goroutine也不会自旋,而是直接放到阻塞队列的尾部.

当G的执行时间小于1ms或者等待队列已经空的时候,就会退出饥饿模式.

goroutine底层实现

GMP模型

G:存储了goroutine的栈信息,状态,任务函数等,在go func的 时候创建,无数量限制,初始栈大概2~4k

M:操作内核级线程,M不保留G的状态,默认数量限制是10000

p:虚拟处理器,P的数量受本机CPU数量的影响,可以设置,只有将M和P绑定才可以让P中runq中

goroutine泄漏的场景

什么是goroutine泄漏

goroutine创建后,长时间得不到释放,一直占着资源,后面还一直创建新的goroutine,最终导致内存耗尽,程序崩溃

泄露场景

  • goroutine内进行channel/mutex等操作一直阻塞
  • 业务逻辑进入死循环

goroutine终止的情况

  • 当goroutine完成的工作
  • 发生了错误
  • 其他协程告诉他终止

go内存分配

内存分配使用了Google的TCmalloc算法,每个线程会自行维护一个独立的内存池,进行内存分配的时候优先从该内存池中分配,当内存池不足的时候才会加锁后向全局内存池中申请,减少了系统调用并且避免了不同线程对全局内存池的争抢

将内存切分的很小,分多级管理,降低锁的粒度

回收对象内部内存的时候,不会真正释放,而是放回之前分配的内存池中;只有内存池中内存闲置过多的时候,才会尝试归还部分内存分配给操作系统.

go内存逃逸机制

什么是内存逃逸

本来应该分配到栈上的数据跑到了堆上,这种现象就叫内存逃逸

逃逸分析

  1. 函数内部变量在函数外部被引用,则必定放到堆上
  2. 如果栈上放不下了,一定会放到堆上

逃逸的情况

  • 函数返回指针变量
  • 栈空间不足
  • 数据结构大小不确定
  • 闭包

内存逃逸带来的后果

  • 栈上分配内存比在堆上分配内存效率更高
  • 堆上的数据回收需要GC,会增加系统的开销
  • 逃逸分析实在编译阶段发生的
  • 逃逸分析的目的是决定将数据分配到哪里
  • 无论变量大小,只要是指针都会在堆上分配,所以小变量推荐值传递,效率反而会高一点

go内存对齐机制

什么是内存对齐

go编译器会把struct结构体做数据对齐,内存对齐:就是使内存地址是所存放数据大小的整数倍

优点

  1. 提高可移植性
  2. 提高内存访问效率

缺点

存在内存浪费,是一种以空间换时间的做法

go的内存对齐原则

  1. 结构体变量中成员的偏移量必须是成员大小的整数倍
  2. 整个结构体的地址必须是最大字节的整数倍

主流GC算法

引用计数

算法

给每个对象维护一个引用计数,引用该对象的对象销毁的时候,引用计数-1,当引用技术为0的时候回收该对象.

代表

Python,PHP,Swift

优点

对象回收快,不会出现内存耗尽或者到达某个阈值的时候再回收

缺点

不能很好的处理循环引用,实时维护引用技术也需要开销

分代回收

算法

按照对象的生命周期长短分为不同的代空间,

语言

java

优点

回收性能好

缺点

算法复杂,耗费资源

标记清除

算法

从根开始遍历所有引用的对象,标记引用对象,没有标记的回收

灰色:对象在标记队列中等待,存放root对象

黑色:对象以标记,不会被回收

白色:对象无标记,回收

步骤
  1. 将所有对象放入白色集合,
  2. 将root放入灰色
  3. 遍历灰色,将自身放入黑色,并将自身引用的节点放入灰色
  4. 重复上述步骤直到灰色中无对象
  5. 回收白色中所有对象

语言

golang(三色标记法)

优点

解决了引用计数的痛点

缺点

需要STW(stop the world),暂停程序运行

GC调优

GC太频繁也会影响效率

本质就是控制堆区的数据

  1. 控制goroutine的数量
  2. 少量使用string的+操作
  3. slice提前分配足够内存避免扩容
  4. 避免map的key对象过多
  5. 变量的复用
  6. 增大GOGC的值,降低GC的运行频率
