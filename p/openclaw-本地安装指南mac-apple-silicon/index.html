OpenClaw 本地安装指南（Mac Apple Silicon）

Apr 22, 2026

适用环境

本文适用于以下环境：

  • macOS（Apple Silicon，例如 M1 / M2 / M3）
  • zsh shell
  • 希望在本机安装并运行 OpenClaw CLI / TUI

如果你使用的是 Intel Mac 或 Linux，部分路径和依赖版本可能需要调整。

安装前检查

在正式安装前，建议先确认系统环境没有问题。

1. 检查系统架构

执行：

1

uname -m

期望输出：

1

arm64

如果输出不是 arm64，说明当前机器不是 Apple Silicon，本文步骤不一定完全适用。

2. 检查 Homebrew

执行：

1
2

brew --version
which brew

期望结果：

  • brew --version 能正常输出版本号
  • which brew 输出类似：
1

/opt/homebrew/bin/brew

如果 brew 不存在，建议先安装 Homebrew，再继续后续步骤。

3. 检查 Node.js 版本

执行：

1

node -v

建议版本：

  • 最低建议：22.14+
  • 更推荐：24+

如果版本过低，后续安装或运行依赖可能会失败。

安装 OpenClaw

不推荐的方式

不要使用全局 npm 安装：

1

npm install -g openclaw

这种方式更容易遇到依赖不一致、版本冲突或后续升级问题。

推荐方式：使用官方安装脚本

执行：

1

curl -fsSL https://openclaw.ai/install-cli.sh | bash

安装完成后，先直接验证 CLI 是否已落盘：

1

~/.openclaw/bin/openclaw --version

期望输出类似：

1

OpenClaw 2026.x.x

配置 PATH

为了在任意终端中直接使用 openclaw，需要把可执行文件目录加入 PATH。

执行：

1
2

echo 'export PATH="$HOME/.openclaw/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

然后验证：

1
2

which openclaw
openclaw --version

期望结果：

1

/Users/xxx/.openclaw/bin/openclaw

如果 which openclaw 没有输出，通常说明 PATH 还没有生效，可以重新打开一个终端再试一次。

初始化 OpenClaw

首次使用建议先执行 onboarding：

1

openclaw onboard --install-daemon

初始化过程中，可以先参考下面这组相对稳妥的选择：

  • Security: Yes
  • Setup: QuickStart
  • Model: DeepSeek
  • Default model: Keep current (deepseek-chat)
  • Channel: Skip for now
  • Web search: Skip
  • Skills: No
  • Hooks: Skip

这套配置的思路是：先把本地环境跑通，复杂能力后续再逐步加。

选择模型

OpenClaw 支持多种模型提供方。对大多数人来说，比较常见的有两种接入方式：

  • 使用 DeepSeek，走 deepseek/*
  • 使用 OpenAI 订阅接入 Codex，走 openai-codex/*

这里最容易混淆的一点是：

  • openai/* 对应 OpenAI API Key
  • openai-codex/* 对应 OpenAI 订阅 / Codex OAuth

如果你使用的是 ChatGPT / Codex 订阅，而不是单独的 OpenAI API Key，就应该选择 openai-codex/*。

方式一：使用 DeepSeek

如果你的目标是先快速跑通 OpenClaw，本地默认用 DeepSeek 往往更省事。

onboarding 时直接选择 DeepSeek

初始化向导里可以这样选：

  • Model: DeepSeek
  • Default model: Keep current (deepseek-chat)

初始化完成后，可以执行：

1

openclaw config get agents.defaults.model.primary

如果输出类似下面这样，说明默认模型已经是 DeepSeek：

1

deepseek/deepseek-chat

你也可以手动切换：

1

openclaw config set agents.defaults.model.primary deepseek/deepseek-chat

然后启动：

1

openclaw tui

如果底部状态栏显示类似：

1

agent main | session main (openclaw-tui) | deepseek/deepseek-chat

说明当前会话已经在使用 DeepSeek。

方式二：使用 OpenAI 订阅接入 Codex

如果你已经有 OpenAI 订阅，希望在 OpenClaw 中使用 Codex，那么应该走 openai-codex provider，而不是 openai provider。

第一步：做 OAuth 登录

执行：

1

openclaw models auth login --provider openai-codex

如果你更喜欢通过向导，也可以执行：

1

openclaw onboard --auth-choice openai-codex

第二步：确认模型已经可用

执行：

1

openclaw models list --provider openai-codex

正常情况下可以看到类似输出：

1

openai-codex/gpt-5.4

第三步：把默认模型切到 Codex

执行：

1

openclaw config set agents.defaults.model.primary openai-codex/gpt-5.4

再确认一次：

1

openclaw config get agents.defaults.model.primary

期望输出：

1

openai-codex/gpt-5.4

第四步：重新进入 TUI

执行：

1

openclaw tui

进入后，如果你此前已经有旧会话，底部状态栏可能仍然显示 deepseek/deepseek-chat。这不是配置没生效，而是当前 session 还在沿用旧模型。

这时可以在 TUI 里执行：

1

/model openai-codex/gpt-5.4

如果还不放心，再执行：

1

/new openai-codex/gpt-5.4

这两步的作用分别是：

  • /model openai-codex/gpt-5.4：把当前 session 切到 Codex
  • /new openai-codex/gpt-5.4：新建一个明确使用 Codex 的会话

切换成功后，底部状态栏应该会显示类似：

1

agent main | session main (openclaw-tui) | openai-codex/gpt-5.4

DeepSeek 和 Codex 该怎么选

如果你只是想先把 OpenClaw 跑通，建议先用 DeepSeek：

  • 配置简单
  • 更容易快速验证链路
  • 适合作为初始默认模型

如果你已经在用 OpenAI 订阅，并且希望在 OpenClaw 里体验 Codex 的代码能力，可以切到 Codex：

  • 适合代码生成、重构、排错这类任务
  • 不需要单独配置 OPENAI_API_KEY
  • 重点是要用 openai-codex/*，不要误配成 openai/*

模型切换时的常见误区

很多人已经把默认模型改成了 Codex，但进入 TUI 后看到的仍然是 DeepSeek，常见原因一般有三个：

  • 只完成了 OAuth 登录，但没有执行 config set 修改默认模型
  • 默认模型已经改了，但当前打开的是旧 session
  • 当前 session 被手动覆盖成了其他模型

所以最稳妥的检查顺序是：

  1. openclaw config get agents.defaults.model.primary
  2. openclaw models list --provider openai-codex
  3. openclaw tui
  4. 在 TUI 中执行 /model openai-codex/gpt-5.4
  5. 必要时再执行 /new openai-codex/gpt-5.4

接入微信

除了在本地终端或 Web UI 中使用 OpenClaw，你也可以把它接到微信上。

不过需要注意：微信不是 OpenClaw 核心内置通道，而是通过外部 channel plugin 接入的。

当前官方文档给出的能力范围大致是：

  • 支持微信私聊
  • 支持媒体消息
  • 群聊能力目前没有在插件能力元数据中明确声明

微信插件名称

OpenClaw 文档里这套微信接入相关名称有几种写法，容易混淆：

  • WeChat：文档里展示给用户看的名字
  • Weixin：腾讯插件侧使用的命名
  • openclaw-weixin：OpenClaw 中的 channel id
  • @tencent-weixin/openclaw-weixin：实际 npm 插件包名

在命令行和配置里，通常使用的是 openclaw-weixin。

安装微信插件

可以直接执行：

1
2
3

openclaw plugins install "@tencent-weixin/openclaw-weixin"
openclaw config set plugins.entries.openclaw-weixin.enabled true
openclaw gateway restart

如果你更喜欢官方提供的一键安装方式，也可以使用：

1

npx -y @tencent-weixin/openclaw-weixin-cli install

安装完成后，建议先检查插件是否已经被识别：

1

openclaw plugins list

登录微信

执行：

1

openclaw channels login --channel openclaw-weixin

然后用手机微信扫描二维码并确认登录。

登录完成后，插件会把账号凭证保存在本地 OpenClaw 状态目录中。之后 Gateway 启动时，会自动尝试拉起这个微信通道。

如果你配置了多个微信账号，官方文档建议把私聊 session 范围设置得更细一些：

1

openclaw config set session.dmScope per-account-channel-peer

查看微信通道状态

接入完成后，可以执行：

1

openclaw channels status --probe

如果你想看更详细的通道状态，也可以执行：

1
2

openclaw channels list
openclaw channels logs --channel openclaw-weixin

微信接入后的权限控制

微信接入后，新的私聊发送方通常仍然会经过 OpenClaw 的 pairing / allowlist 机制。

你可以先查看待审批对象：

1

openclaw pairing list openclaw-weixin

然后审批：

1

openclaw pairing approve openclaw-weixin <CODE>

这样可以避免任何拿到微信入口的人都直接和 agent 建立会话。

Plugin 和 Skill 的区别

很多人在第一次接触 OpenClaw 时，会把 plugin 和 skill 混在一起。实际上它们不是一回事。

Plugin 是什么

plugin 更像是系统功能扩展，用来给 OpenClaw 增加新的能力。

常见用途包括：

  • 新增聊天渠道
  • 新增外部工具接入
  • 新增运行时能力

比如微信接入用到的 @tencent-weixin/openclaw-weixin，本质上就是一个 channel plugin。它负责让 OpenClaw 具备“连接微信、扫码登录、收发消息”的能力。

Skill 是什么

skill 更像是给 agent 增加一套专门的提示、规则和工作流程。

它通常用于：

  • 约束 agent 的回答方式
  • 补充某个领域的专用知识
  • 给 agent 增加一套稳定可复用的执行模板

例如：

  • 代码审查 skill
  • 文档写作 skill
  • 某个 API 的专用操作说明

这些 skill 会影响 agent 怎么做事，但不会直接增加一个微信通道、Slack 通道或者其他系统级能力。

怎么理解两者的关系

你可以把它们理解成：

  • plugin 解决“OpenClaw 能不能做这件事”
  • skill 解决“agent 应该怎么把这件事做好”

拿微信举例：

  • 微信 plugin：让 OpenClaw 能接入微信
  • skill：告诉 agent 在微信里应该如何回复、如何执行业务流程、如何遵循某种沟通规范

所以，微信接入属于 plugin，不是 skill。

安装完成后的验证

如果安装和初始化都正常，通常会看到类似提示：

1
2

Gateway service installed
Onboarding complete

这时可以继续做下面几项基础验证。

1. 启动 TUI 

1

openclaw tui

如果能正常进入终端界面，说明 CLI 主流程已经可用。

2. 打开 Web UI

如果 OpenClaw 启动了本地 Web 界面，可以在浏览器访问：

1

http://127.0.0.1:18789/#token=你的token

实际端口或 token 可能会因版本不同略有差异，按终端输出为准。

3. 做最小测试

进入 TUI 或 Web UI 后，可以直接输入：

1

你好

如果能够正常返回内容，说明基础链路已经打通。

常见问题

1. openclaw: command not found

报错示例：

1

zsh: command not found: openclaw

处理方式：

1

export PATH="$HOME/.openclaw/bin:$PATH"

如果临时执行后恢复正常，再把它写入 ~/.zshrc 即可。

2. onboarding 过程缺少依赖

如果出现类似错误：

1

Error: Cannot find module '@larksuiteoapi/node-sdk'

可以执行：

1

npm install --prefix "$HOME/.openclaw/lib/node_modules/openclaw" --legacy-peer-deps @larksuiteoapi/node-sdk

然后重新执行：

1

openclaw onboard --install-daemon

这个问题通常是某些可选能力依赖没有正确安装导致的。

3. 卡在 Bootstrap pending

可以尝试删除缓存文件后重新进入：

1
2

rm ~/.openclaw/workspace/BOOTSTRAP.md
openclaw tui

如果问题仍然存在，可以继续检查日志。

4. 查看日志

执行：

1

tail -f ~/.openclaw/logs/gateway.log

排查本地启动失败、网关未就绪、模型调用异常时，这个日志通常最有帮助。

使用建议

第一次安装时，建议遵循下面这个顺序：

  1. 先确认系统架构、Homebrew、Node.js 版本
  2. 使用官方安装脚本安装 CLI
  3. 配置 PATH
  4. 执行 onboard
  5. 先跳过不必要的高级功能
  6. 用 tui 或 Web UI 做最小可用验证

一个比较稳妥的原则是：

先跑通主流程，再逐步扩展飞书、微信、skills 或其他集成功能。

总结

OpenClaw 在 Mac Apple Silicon 上安装并不复杂，真正容易卡住的地方主要是：

  • PATH 没有配置好
  • Node.js 版本偏低
  • onboarding 阶段某些可选依赖缺失

只要先完成基础环境检查，再按“官方安装 -> 配置 PATH -> onboarding -> 验证运行”的顺序推进，通常都能比较顺利地跑起来。
