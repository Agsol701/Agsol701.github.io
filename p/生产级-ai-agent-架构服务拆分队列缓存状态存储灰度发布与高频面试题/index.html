生产级 AI Agent 架构：服务拆分、队列、缓存、状态存储、灰度发布与高频面试题

source: agent-production-architecture
May 20, 2026

写在前面

Demo 级 Agent 可以写在一个脚本里。

生产级 Agent 需要处理并发、权限、状态、成本、失败恢复、可观测性和灰度发布。

一、生产级 Agent 的整体架构

1.1 基本组件 

flowchart TD
    U[用户入口] --> API[Agent API]
    API --> ORCH[Orchestrator]
    ORCH --> LLM[LLM Gateway]
    ORCH --> TOOL[Tool Gateway]
    ORCH --> STATE[State Store]
    ORCH --> MEM[Memory Store]
    TOOL --> BUS[业务系统]
    ORCH --> OBS[Trace and Metrics]
    ORCH --> QUEUE[Task Queue]

1.2 组件职责

组件 职责
Agent Application Programming Interface（API，应用程序编程接口） 接收请求、鉴权、返回结果
Orchestrator 控制 Agent Loop 和工作流
Large Language Model（LLM，大语言模型）Gateway 统一模型调用、限流和降级
Tool Gateway 管理工具调用、权限和审计
State Store 保存任务状态
Memory Store 保存长期记忆
Task Queue 处理异步任务
Observability 记录 trace、指标和日志

二、LLM Gateway

2.1 为什么需要统一网关

统一 LLM Gateway 可以处理：

  • 模型路由
  • 限流
  • 重试
  • 降级
  • 成本统计
  • prompt 版本
  • 安全过滤

2.2 模型路由

不同任务可以使用不同模型：

任务 模型策略
简单分类 低成本模型
工具参数生成 稳定模型
长报告生成 长上下文模型
高风险决策 更强模型加验证

三、Tool Gateway

3.1 工具统一入口

Tool Gateway 负责：

  • 参数校验
  • 权限校验
  • 超时控制
  • 重试策略
  • 审计日志
  • 返回结构标准化

3.2 工具不要直接暴露给模型

模型只生成调用意图和参数，真正执行必须通过程序侧网关。

四、状态和存储

4.1 State Store

State Store 保存当前任务执行状态。

适合使用：

  • Redis 保存短期状态
  • MySQL 或 PostgreSQL 保存持久任务记录
  • 对象存储保存大文件和中间产物

4.2 Memory Store

Memory Store 保存长期记忆，可以结合：

  • 关系数据库
  • 向量数据库
  • 文档数据库
  • 权限系统

五、异步任务

5.1 为什么需要队列

长任务不应该阻塞请求线程。

适合放入队列：

  • 批量文档处理
  • 报告生成
  • 多工具串行执行
  • 大规模评估

5.2 队列设计要点

需要关注：

  • 幂等
  • 重试
  • 死信队列
  • 超时
  • 任务取消
  • 进度查询

六、灰度与回滚

6.1 需要灰度的内容

Agent 中这些内容都可能需要灰度：

  • 模型版本
  • prompt 版本
  • 工具 schema
  • 工作流规则
  • memory 策略
  • rerank 策略

6.2 回滚能力

上线前要能快速回滚到旧版本。

没有回滚能力，不适合频繁调整 Agent 行为。

七、成本控制

7.1 成本来源

Agent 成本包括：

  • 模型输入 token
  • 模型输出 token
  • embedding
  • rerank
  • 工具 API
  • 存储和日志

7.2 优化方式

常见优化：

  • 缓存工具结果
  • 压缩上下文
  • 简单任务用小模型
  • 限制最大轮次
  • 批量处理
  • 失败快速停止

八、常见面试题

8.1 生产级 Agent 和 Demo 最大区别是什么？

生产级 Agent 需要处理权限、状态、失败恢复、可观测性、成本、并发、灰度和回滚。

8.2 为什么需要 LLM Gateway？

LLM Gateway 可以统一处理模型路由、限流、重试、降级、成本统计和 prompt 版本管理。

8.3 为什么需要 Tool Gateway？

Tool Gateway 可以在程序侧强制执行参数校验、权限控制、超时、审计和返回结构标准化。

8.4 长任务为什么要异步化？

长任务会阻塞请求并增加失败风险。异步队列可以支持重试、进度查询、取消和断点恢复。

8.5 Agent 成本怎么控制？

可以通过模型分层、上下文压缩、缓存、最大轮次限制、批量处理和失败快速停止来控制成本。
