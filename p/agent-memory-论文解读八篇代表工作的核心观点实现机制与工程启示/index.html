Agent Memory 论文解读：八篇代表工作的核心观点、实现机制与工程启示

source: agent-memory-papers
Oct 09, 2026

写在前面

为智能体（Agent）接入数据库，只完成了记忆系统的存储部分。真正影响任务效果的是：哪些信息值得写入，如何处理变化，什么时候检索，以及取回的信息能否帮助决策。

本文整理八篇与 Agent Memory（智能体记忆）工程实践相关的论文，面向希望理解并实现记忆系统的开发者。范围包括上下文管理、事实更新、时态知识、动态组织、经验学习和评测，不是截至写作日期的完整文献综述。

文中的 LLM（Large Language Model，大语言模型）指负责推理、生成或记忆操作决策的模型。RAG（Retrieval-Augmented Generation，检索增强生成）指通过检索外部信息补充生成上下文的方式。各章分别说明论文方法与本文的工程建议；建议中的数据字段和组合架构不应被当作论文提供的统一接口。

一、八篇论文分别解决什么问题

工作 首次公开年份 核心问题 主要机制
MemGPT 2023 有限上下文如何利用外部信息 分层记忆与自主搬运
Reflexion 2023 如何避免重复失败 反馈驱动的语言反思
ExpeL 2023 如何跨任务积累经验 经验对比与规则提炼
LongMemEval 2024 如何测量长期记忆能力 多会话问答评测
Zep 2025 如何保存变化的事实 双时态知识图谱
A-MEM 2025 如何动态组织记忆 原子笔记、关联与演化
Mem0 2025 如何增量维护事实 提取与更新流水线
AgeMem 2026 如何学习记忆管理策略 统一工具动作与强化学习

年份按 arXiv 首次公开时间记载，会议发表时间可能不同。具体来源见各章论文链接。

阅读时可以把记忆系统拆成三个层次：表示什么、如何管理、怎样验证。向量、图和笔记属于表示；提取、更新、反思和调度属于管理；评测负责检验前两者的效果。

二、MemGPT：把上下文管理理解为分层内存

论文：MemGPT: Towards LLMs as Operating Systems。

2.1 核心观点与理论依据

MemGPT 借鉴 OS（Operating System，操作系统）的分层内存思想：当前上下文类似容量有限的主存，外部存储类似磁盘。通过按需搬运信息，模型可以利用超出单次上下文容量的材料。它没有扩大模型本身的上下文上限。论文方法

2.2 实现机制

主上下文包含固定系统指令、近期对话和可编辑工作区。外部信息分为完整事件历史的回忆存储，以及保存事实、偏好或文档的归档存储。模型通过函数调用搜索、读写和搬运信息；系统在容量压力下管理近期对话，并通过控制流支持连续操作。论文方法

flowchart LR
    A[当前上下文：指令、近期对话、工作区] --> B[模型决定记忆操作]
    B --> C[外部回忆与归档存储]
    C --> D[取回相关信息]
    D --> A

2.3 工程启示与边界

**本文建议：**将当前目标和未完成事项留在工作区，大型工具输出保存到外部，仅加载必要片段。需要记录每次检索的收益和调用成本，避免模型反复搜索。

分层存储解决容量分配问题；信息已经保存，并不意味着模型一定能找到或正确使用它。

三、Mem0：把记忆写入变成增量更新

论文：Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory。

3.1 核心观点与理论依据

Mem0 将长期记忆看作持续维护的显著事实集合。对话摘要提供整体背景，近期消息提供细节，新交互提供本次增量。写入前对比已有记忆，减少重复与矛盾。论文方法

3.2 实现机制

提取阶段使用摘要、近期历史和新消息对生成候选事实。更新阶段为每条事实检索相似记忆，由模型选择新增、更新、删除或不操作。论文还提出图扩展版本，用实体和关系表示关联事实。论文方法

flowchart TD
    A[新交互、近期消息、摘要] --> B[提取候选事实]
    B --> C[检索相似旧记忆]
    C --> D{判断如何维护}
    D --> E[新增]
    D --> F[更新]
    D --> G[删除]
    D --> H[不操作]

3.3 工程启示与边界

**本文建议：**将模型输出视为待执行的变更计划，存储层校验目标和版本后再提交，并保留原文证据。示例字段可以包含 source_message_id、revision 和 updated_at；这些是工程设计，不是论文的统一字段约定。

相似记忆召回遗漏会影响更新判断。针对历史变化的处理，还需要区分“原事实错误”和“原事实过去成立”。

四、Zep：用双时态模型保存动态事实

论文：Zep: A Temporal Knowledge Graph Architecture for Agent Memory。

4.1 核心观点与理论依据

同一事实具有两种时间：现实中何时有效，以及系统何时获知、记录或失效。Zep 通过双时态知识图谱表达这种差异，并保留事实与来源事件的联系。论文方法

4.2 实现机制

原始消息进入事件层；模型抽取实体和事实，经实体消歧与关系去重写入语义层，社区层组织相关实体。事实边记录现实有效区间与系统记录时间。相对日期根据消息参考时间解析，冲突事实可使旧边失效，检索结合语义、全文与图结构。论文方法

4.3 工程启示与边界

**本文示例：**用户十月说“我九月搬到上海”。现实有效时间从九月开始，系统获知时间在十月。旧居住地记录可结束有效期，仍用于回答历史问题。

本文建议先在关系表中实现有效区间与来源引用，再评估是否需要图数据库。时间解析、实体消歧和冲突判断都可能出错，图结构本身不能保证事实正确。

五、A-MEM：通过原子笔记建立动态记忆网络

论文：A-MEM: Agentic Memory for LLM Agents。

5.1 核心观点与理论依据

A-MEM 借鉴 Zettelkasten（卡片笔记法），用独立笔记与灵活链接组织信息。模型参与记忆结构的生成和演化，而不只在固定索引上检索。论文方法

5.2 实现机制

笔记保存原始内容、时间、关键词、标签、上下文描述、向量和关联。新笔记先检索相关历史笔记，再由模型判断是否建立链接；新信息还可以触发旧笔记语义属性的更新。查询利用笔记的语义表示和关联组织获取相关记忆。论文方法

5.3 工程启示与边界

**本文建议：**对跨事件问题，可先通过语义检索找到相关记忆笔记，再在上下文预算内沿笔记链接加载关联事件。例如将发布故障与此前的依赖变更关联，为后续定位提供证据。这里的“笔记”是 A-MEM 存储的记忆单元；语义检索与关联展开则是读取这些记忆的方式。

原文、模型生成描述和关联关系应分别保存并记录版本。模型建立的链接表示推测出的关联，不能自动当作因果证据；错误演化也可能影响后续检索。

六、Reflexion：通过语言反馈改进后续尝试

论文：Reflexion: Language Agents with Verbal Reinforcement Learning。

6.1 核心观点与理论依据

Reflexion 用语言反思改变下一次尝试的上下文，无须通过这一过程更新模型权重。执行经历、评价反馈与反思文本形成一个可重复的改进闭环。论文

6.2 实现机制

执行者完成任务，评价者提供反馈，反思模块结合轨迹和反馈生成改进信息，将其放入情景记忆，再用于下一次尝试。反馈可以来自外部环境，也可以来自内部评价。论文

flowchart LR
    A[执行任务] --> B[获得结果与反馈]
    B --> C[生成反思]
    C --> D[保存情景记忆]
    D --> E[调整下一次尝试]
    E --> A

6.3 工程启示与边界

**本文建议：**反思应包含具体失败证据和可执行修正。例如测试失败后，记录遗漏的输入分支与需要补充的处理步骤，比“下次更仔细”更有用。

反思质量依赖反馈可靠性。重试成功也不足以证明总结出的原因正确，更不应立即将一次反思提升为所有任务适用的规则。

七、ExpeL：从多次经历中提炼跨任务经验

论文：ExpeL: LLM Agents Are Experiential Learners。

7.1 核心观点与理论依据

ExpeL 将经验用于两个层次：具体成功轨迹可以作为新任务的参考实例，多次经历可以抽象成自然语言经验。知识积累发生在外部经验库与上下文中，不要求修改模型权重。论文方法

7.2 实现机制

先收集成功与失败经历，再对比成功失败案例或分析多条成功轨迹。模型维护经验列表，通过新增、赞成、反对和编辑操作调整经验。新任务使用提炼出的经验及检索到的成功案例辅助执行。论文方法

7.3 工程启示与边界

**本文建议：**经验库同时保留具体轨迹和抽象规则，为规则注明任务类型、环境条件及反例。比如“提交前检查必填字段”应关联实际表单场景和验证结果。

相较 Reflexion 的反馈重试闭环，ExpeL 更关注跨任务积累。历史任务分布变化时，旧经验可能失效；语言表述合理不等于迁移效果已经验证。

八、LongMemEval：把长期记忆拆成可测量能力

论文：LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory。

8.1 核心观点与理论依据

LongMemEval 是评测基准，检验系统能否从长期交互中提取信息、跨会话推理、理解时间、处理知识更新，以及在证据不足时拒答。它包含 500 道人工整理的问题。论文方法

8.2 实现机制与实验发现

系统处理带时间信息的多会话历史，再回答相关问题。论文将记忆系统拆成索引、检索和阅读三个阶段，研究存储粒度、索引键、查询和阅读策略。实验发现轮次粒度具有优势，过度压缩为用户事实可能丢失信息；扩展索引键有助于召回。论文方法

8.3 工程启示与边界

**本文建议：**保留事实到原始轮次的引用，将事实用于搜索，将原始上下文用于核验。

能力 示例问题
信息提取 用户明确选择了哪种方案？
跨会话推理 哪些历史约束共同影响当前选择？
时间推理 搬家前用户住在哪里？
知识更新 用户最后确认的语言偏好是什么？
拒答 从未提供过的信息是否被编造？

问答准确率不能直接代表工具执行成功率。业务评测还应加入实际动作、端到端成本与错误使用记忆的案例。

九、AgeMem：通过强化学习统一记忆管理

论文：Agentic Memory: Learning Unified Long-Term and Short-Term Memory Management for Large Language Model Agents。

9.1 核心观点与理论依据

AgeMem 将 LTM（Long-Term Memory，长期记忆）与 STM（Short-Term Memory，短期记忆）的管理纳入同一个决策策略。记忆操作会影响后续任务表现，因此可以作为具有长期收益的动作学习。论文方法

9.2 实现机制

系统通过工具动作暴露存储、更新、检索和上下文管理能力。训练使用 RL（Reinforcement Learning，强化学习）：先学习长期存储，再学习短期上下文管理，最后协调二者。论文设计逐步 GRPO（Group Relative Policy Optimization，组相对策略优化），处理跨阶段、稀疏且不连续的奖励。论文方法

9.3 工程启示与边界

**本文建议：**先定义可观测的记忆动作，记录操作前后状态和任务结果，再判断是否具备训练条件。

AgeMem 涉及策略训练，与给现有模型增加记忆工具存在实现成本差异。奖励设计、训练数据和分布变化都需要单独验证；A-MEM 的主要研究对象则是记忆组织与演化，两者不应混为同一方法。

十、把论文机制组合成工程系统

10.1 统一理解：记忆包含两个决策问题

以下是本文的分析框架，不是某篇论文的统一公式。

设历史交互为 H，持久记忆为 M，当前任务为 q。写入策略决定如何从历史增量维护 M；读取策略决定从 M 选择哪些证据用于回答 q。任务效果同时依赖这两个策略，也依赖模型如何理解取回的信息。

Mem0 和 Zep 重点处理事实维护，A-MEM 重点处理结构演化，MemGPT 处理上下文搬运，Reflexion 和 ExpeL 处理经验转化，AgeMem 学习管理动作，LongMemEval 检验系统能力。

10.2 建议的组合架构

下面是本文提出的工程组合，不是已经由八篇论文共同验证的系统。

flowchart TD
    A[对话与工具事件] --> B[保留原始记录与来源]
    B --> C[事实提取与增量更新]
    B --> D[任务反馈与经验提炼]
    C --> E[事实库：版本与有效区间]
    D --> F[经验库：适用条件与结果]
    Q[当前任务] --> R[限定访问范围后检索]
    E --> R
    F --> R
    R --> S[核验来源与控制上下文预算]
    S --> T[模型回答或执行]
    T --> U[任务评测与成本记录]
    U --> D

可先从原始记录、事实库和更新流水线开始，随后根据业务需要引入时态字段或经验库。只有确实需要关系推理时，再增加动态关联或图检索。

10.3 实现时需要验证的关键假设

  • **压缩是否丢信息：**同时比较原始轮次、摘要、原子事实以及混合表示。
  • **更新是否正确：**区分重复、补充、更正和状态变化，构造对应案例。
  • **检索是否有效：**分别统计证据召回、最终答案和任务成功情况。
  • **成本是否转移：**读取变快时，还要计算提取、合并和重建索引的开销。
  • **经验是否能迁移：**在未参与经验提炼的任务上验证，避免测试答案进入经验库。

对照实验至少包含无长期记忆、完整历史、普通 RAG 和候选记忆系统。尽量固定回答模型、任务集合和评价方式，分别记录写入、检索与生成阶段。论文各自报告的成绩不能脱离模型、数据和预算直接排序。

十一、常见高频面试题

11.1 外部记忆和模型微调有什么区别？

**答：**外部记忆通过可读写的数据和上下文影响行为，微调通过训练改变模型参数。前者可以逐条追踪、修改和删除；后者将能力变化编码到参数中。Reflexion 和 ExpeL 的经验利用不要求修改权重，AgeMem 则训练记忆管理策略。

11.2 MemGPT 是否实现了无限上下文？

**答：**它让模型按需利用外部存储，单次调用仍受上下文容量限制。外部材料需要检索和搬运，任务效果仍取决于选择是否正确以及信息是否被有效使用。

11.3 Mem0 和 Zep 的主要区别是什么？

**答：**Mem0 重点是候选事实与已有记忆之间的增量维护，Zep 重点是动态实体关系及其时间语义。一个系统可以同时采用更新流水线和时态记录，不必将两者理解为互斥的存储方案。

11.4 Reflexion 和 ExpeL 如何帮助 Agent 学习？

**答：**Reflexion 将反馈转成反思，用于后续尝试；ExpeL 从多条轨迹抽取跨任务经验，并检索成功案例辅助新任务。工程上应同时验证反馈质量与经验适用条件。

11.5 为什么只保存原子事实可能不够？

**答：**抽取可能丢失主体、条件、时间和对话语境。事实适合索引，原始轮次适合回溯核验。LongMemEval 的粒度实验提醒我们，压缩效率与信息保真需要一起评估。

11.6 A-MEM 与 AgeMem 的区别是什么？

**答：**A-MEM 研究笔记生成、关联和结构演化；AgeMem 研究如何训练统一的长短期记忆管理策略。前者可以作为外部记忆组织模块，后者还需要训练与奖励设计。
