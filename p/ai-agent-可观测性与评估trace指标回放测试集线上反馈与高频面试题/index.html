AI Agent 可观测性与评估：Trace、指标、回放、测试集、线上反馈与高频面试题

source: agent-observability-evaluation
May 21, 2026

写在前面

Agent 一旦能调用工具，问题排查就比普通问答复杂很多。

用户只说“它没完成任务”，你需要知道到底是意图识别错了、工具选错了、参数错了、工具失败了，还是最终总结错了。

一、为什么 Agent 必须可观测

1.1 只记录最终答案不够

Agent 的失败可能发生在任何环节：

flowchart TD
    A[用户输入] --> B[意图识别]
    B --> C[计划生成]
    C --> D[工具选择]
    D --> E[参数生成]
    E --> F[工具执行]
    F --> G[状态更新]
    G --> H[最终回答]

只看最终答案无法定位问题。

1.2 Trace 是排查基础

每次 Agent 执行都应该有 trace_id，贯穿模型调用、工具调用、状态更新和最终输出。

二、Trace 应该记录什么

2.1 核心字段

字段 说明
trace_id 一次任务的全局 ID
user_id 用户 ID 或匿名 ID
session_id 会话 ID
step_id 当前步骤 ID
model 使用的模型
prompt_version Prompt 版本
tool_name 工具名称
latency_ms 耗时
cost 成本
status 成功或失败

2.2 工具调用日志

工具调用需要记录：

  • 工具名
  • 参数摘要
  • 权限检查结果
  • 执行耗时
  • 返回状态
  • 错误类型

敏感参数要脱敏。

三、评估指标

3.1 任务级指标

任务级指标关注 Agent 是否完成用户目标：

  • task success rate
  • user satisfaction
  • completion time
  • human intervention rate
  • failure rate

3.2 步骤级指标

步骤级指标关注每一步是否正确：

  • intent accuracy
  • tool selection accuracy
  • argument accuracy
  • tool success rate
  • retry count
  • invalid action rate

3.3 成本和性能指标

需要关注：

  • 平均延迟
  • P95 latency（95 分位延迟）
  • token 消耗
  • 工具调用次数
  • 模型调用次数
  • 单任务成本

四、离线评估

4.1 Golden Tasks

为 Agent 准备一批标准任务，例如：

任务 期望结果
查询报销制度 调用文档检索并引用制度
创建报销草稿 生成草稿但不直接提交
查询订单状态 调用订单工具并返回状态

4.2 回归测试

每次修改 prompt、工具 schema、模型或工作流，都应该跑回归测试。

否则一个小改动可能导致其他任务退化。

五、线上反馈

5.1 用户反馈

用户反馈可以包括：

  • 有用或无用
  • 是否完成任务
  • 错误类型选择
  • 自由文本反馈

5.2 失败样本回流

线上失败样本应该进入：

  • 标注队列
  • 回归测试集
  • prompt 优化
  • 工具修复
  • 工作流调整

六、对话回放

6.1 为什么需要回放

回放可以复现一次 Agent 执行过程，帮助定位：

  • 哪个 prompt 版本出错
  • 哪个工具参数错了
  • 哪个状态转移不合理
  • 哪个模型版本行为变化

6.2 回放注意事项

回放要注意：

  • 固定模型版本
  • 固定 prompt 版本
  • 固定工具返回或使用 mock
  • 脱敏用户数据

七、常见面试题

7.1 Agent 评估和 Retrieval-Augmented Generation（RAG，检索增强生成）评估有什么区别？

RAG 评估重点是检索、重排、上下文和生成质量；Agent 评估还要看任务完成率、工具选择、参数正确性、状态转移和执行成功率。

7.2 Agent Trace 应该记录什么？

应记录模型调用、prompt 版本、工具调用、参数、结果、状态变化、延迟、成本和错误信息。

7.3 什么是 task success rate？

它表示 Agent 是否真正完成用户目标，而不是只生成了看起来合理的回答。

7.4 为什么需要对话回放？

回放可以复现历史执行过程，帮助定位模型、prompt、工具或状态机的问题。

7.5 线上失败样本怎么利用？

可以进入标注、回归测试、prompt 优化、工具修复和工作流调整闭环。
