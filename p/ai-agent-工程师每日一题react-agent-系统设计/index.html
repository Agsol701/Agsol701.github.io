AI Agent 工程师每日一题：ReAct Agent 系统设计

May 20, 2026

🎯 AI Agent 工程师每日一题 · 2026年05月20日 题目 请设计一个基于 ReAct (Reasoning + Acting) 框架的 Agent 系统,用于自动化处理用户的复杂查询任务(如"帮我分析最近一周的销售数据并生成报告")。要求:

  1. 描述 ReAct 框架的核心思想和执行流程
  2. 设计该 Agent 的 Prompt 结构(包括 System Prompt 和 Few-shot 示例)
  3. 如何处理工具调用失败和推理陷入循环的情况?
  4. 用伪代码实现 ReAct 的主循环逻辑 题解 核心要点
  5. ReAct 核心思想: 将推理(Reasoning)和行动(Acting)交织进行,让 LLM 在执行动作前先进行思考,并在行动后观察结果再继续推理,形成 Thought → Action → Observation 的循环
  6. 提示词设计: 需要明确定义可用工具列表、输出格式规范、示例对话,引导模型按固定格式输出思考和动作
  7. 错误处理: 设置最大重试次数、检测循环模式、提供错误反馈给 LLM 让其调整策略
  8. 循环控制: 设置最大迭代次数、检测任务完成标志(如 Final Answer)、监控重复动作

Prompt 结构示例 System Prompt: 你是一个智能助手,可以使用工具来回答用户问题。请按照以下格式思考和行动:

Thought: [你的推理过程,分析当前情况和下一步计划] Action: [工具名称] Action Input: [工具参数,JSON格式]

观察结果后继续思考,直到能给出最终答案。

可用工具:

  • query_database: 查询销售数据库,参数 {“sql”: “SQL语句”, “date_range”: “日期范围”}
  • generate_chart: 生成图表,参数 {“data”: […], “chart_type”: “bar/line/pie”}
  • create_report: 生成报告文档,参数 {“title”: “标题”, “content”: “内容”}

当你准备好最终答案时,使用: Final Answer: [你的最终回答]

Few-shot 示例: 用户: 帮我查询昨天的订单总数 Thought: 用户想知道昨天的订单总数,我需要先查询数据库 Action: query_database Action Input: {“sql”: “SELECT COUNT(*) FROM orders WHERE date = ‘2026-05-19’”, “date_range”: “2026-05-19”} Observation: 查询结果: 1250 条订单

Thought: 已获取数据,可以直接回答用户 Final Answer: 昨天(2026-05-19)共有 1250 条订单。

伪代码实现 def react_agent(user_query, max_iterations=10): “““ReAct Agent 主循环””” history = [] iteration = 0 action_history = [] # 记录动作历史,用于检测循环

while iteration < max_iterations:
    # 构造 prompt (system + few-shot + history + user_query)
    prompt = build_prompt(user_query, history)
    # 调用 LLM 生成响应
    response = llm.generate(prompt)
    # 解析响应
    thought, action, action_input = parse_response(response)

    # 检测是否完成
    if "Final Answer" in response:
        return extract_final_answer(response)

    # 检测循环: 如果连续3次执行相同动作,介入处理
    if is_repeated_action(action, action_input, action_history, threshold=3):
        error_feedback = "你似乎陷入了循环,请尝试不同的方法或使用其他工具"
        history.append({"role": "system", "content": error_feedback})
        iteration += 1
        continue

    # 执行动作
    try:
        observation = execute_tool(action, action_input)
        if observation.error:
            observation_text = f"错误: {observation.error}。请检查参数或尝试其他方法"
        else:
            observation_text = f"成功: {observation.result}"
    except Exception as e:
        observation_text = f"工具执行异常: {str(e)}"

    # 更新历史
    history.append({"thought": thought, "action": action, "action_input": action_input, "observation": observation_text})
    action_history.append((action, action_input))
    iteration += 1

return "抱歉,任务过于复杂,未能在限定步骤内完成"

原理 ReAct 的理论基础 ReAct 结合了两种互补的能力:

  1. 推理(Reasoning): 帮助 Agent 规划、追踪进度、处理异常,类似于人类的"内心独白"
  2. 行动(Acting): 与外部环境交互,获取信息或改变状态 关键创新在于将二者**交织(interleave)*而非分离,形成推理指导行动、行动结果反馈推理的闭环。 数学建模(MDP 视角) 可以将 ReAct 建模为部分可观测马尔可夫决策过程(POMDP): • 状态空间 S: 环境的完整状态(Agent 不完全可见) • 动作空间 A: 可用工具集合 + 特殊动作(如 Final Answer) • 观测空间 O: 工具返回的结果 • 策略 π: LLM 的生成策略,基于历史 (thought, action, observation) 序列决定下一步 ReAct 的目标是最大化任务完成概率: π = argmax_π P(达成目标 | π, 用户查询)

通过 Thought 这一"内部动作",Agent 能够: • 规划: 分解复杂任务为子目标序列 • 反思: 检测错误并调整策略 • 泛化: 将少样本示例的模式应用到新场景 为什么 Thought 很重要? 研究表明,移除 Thought 后,Agent 性能显著下降: • 无 Thought: Action 选择缺乏连贯性,容易陷入局部最优 • 有 Thought: 模型能显式推理因果关系,提前规划多步路径 类比: Thought 类似于人类的"工作记忆",帮助维持任务上下文和中间结果。

延伸

  1. ReAct vs. Plan-and-Execute,如何选择? ReAct (交织式): • 优势: 灵活应对动态环境,可根据中间结果调整计划 • 劣势: 可能频繁切换工具,效率较低 • 适用: 信息不完整、需要探索式搜索的任务(如调试、研究) Plan-and-Execute (分离式): • 优势: 一次性生成完整计划,执行效率高,可并行调用工具 • 劣势: 计划一旦确定难以调整,对初始信息依赖高 • 适用: 任务结构清晰、环境可预测的场景(如数据分析流水线) 混合策略: 高层用 Plan-and-Execute 规划阶段,每个阶段内用 ReAct 处理细节。

  2. 如何在生产环境中监控 ReAct Agent 的质量? 关键指标: • 任务完成率: 成功给出 Final Answer 的比例 • 平均迭代次数: 反映效率,过高说明规划能力不足 • 工具调用成功率: 监控参数错误率、超时率 • 循环检测触发率: 高触发率说明 Prompt 或工具设计有问题 • 用户满意度: 通过反馈收集人类评价 可视化手段: • 记录每个 session 的 Thought-Action-Observation 序列 • 构建工具调用图,分析常见路径和异常分支 • A/B 测试不同 Prompt 版本

  5. 工具参数校验: 在执行前检查参数合法性(如 SQL 注入检测、文件路径校验)

  6. 输出过滤: 对工具返回结果做清洗,移除敏感信息或噪声

  7. 置信度评估: 要求 LLM 输出置信度分数,低于阈值时要求人工审核 Prompt 技巧: • 明确告知"如果不确定,优先使用搜索工具而非猜测” • Few-shot 中包含"承认不知道"的示例 • 引入 self-consistency: 多次采样并投票选择最一致的动作 每日坚持学习,面试稳稳拿下!💪
