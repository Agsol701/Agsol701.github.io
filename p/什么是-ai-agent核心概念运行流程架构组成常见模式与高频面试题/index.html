什么是 AI Agent：核心概念、运行流程、架构组成、常见模式与高频面试题

May 18, 2026

写在前面

AI Agent 解决的核心问题是：

模型理解目标后，如何通过工具、状态和流程完成任务。

所以 Agent 不是一个更大的 prompt，也不是“会联网的聊天机器人”。它更像是一套任务执行系统：模型负责理解、判断和决策，工具负责连接真实世界，状态负责记录进展，工作流负责约束过程。

一、AI Agent 到底是什么

1.1 最直白的理解

可以把 AI Agent 理解成：

能围绕一个目标，自主选择步骤、调用工具、观察结果并持续推进任务的智能应用。

普通聊天机器人通常是：

1

用户问题 -> 模型回答

Agent 通常是：

1

用户目标 -> 任务理解 -> 制定计划 -> 调用工具 -> 观察结果 -> 更新状态 -> 继续执行或结束

1.2 知识检索在 Agent 中的位置

有些 Agent 需要查询外部知识，例如制度文档、产品手册、历史工单或代码仓库。此时知识检索可以作为 Agent 的一个工具，也可以作为 Agent 的知识供给层。

但知识检索不是 Agent 的前置条件，也不等于 Agent 本身。它只是 Agent 在完成任务时可能使用的一类能力。

场景 关注点
知识检索 从外部资料中找到相关信息
Agent 围绕目标规划步骤、调用工具、更新状态并完成任务
二者结合 Agent 在执行任务时调用知识检索工具获取依据

1.3 Agent 不等于完全自主

生产系统中的 Agent 通常不是完全放开执行，而是“有限自主”：

  • 可调用的工具有限
  • 可访问的数据有限
  • 高风险操作需要确认
  • 执行轮次有上限
  • 关键节点有日志和审计

越接近真实业务，越需要把 Agent 放进明确边界里。

二、Agent 的核心组成

2.1 LLM

LLM 是 Agent 的决策核心，负责理解用户目标、选择下一步动作、解释工具结果、生成最终输出。

但 LLM 本身不应该直接承担所有职责。它适合做判断和语言推理，不适合替代数据库、权限系统、计算引擎和业务规则。

2.2 Tools

工具让 Agent 能影响外部世界，例如：

  • 查询数据库
  • 检索知识库
  • 调用 HTTP API
  • 发送邮件
  • 创建工单
  • 运行代码
  • 读取文件

工具越强，越要重视权限、校验、日志和审批。

2.3 State

状态记录任务当前进展，包括：

  • 用户目标
  • 已完成步骤
  • 工具调用结果
  • 中间变量
  • 错误信息
  • 等待用户确认的事项

没有状态管理，Agent 很容易重复执行、遗漏步骤或者无法恢复。

2.4 Memory

记忆用于跨轮次保存有价值的信息。它可以保存用户偏好、历史任务、业务事实和长期上下文。

记忆不是越多越好。错误记忆比没有记忆更危险。

2.5 Workflow

工作流用于约束 Agent 的行为边界。

例如报销 Agent 可以被设计成：

3.2 什么时候继续，什么时候停止

Agent 必须有明确停止条件：

  • 已完成用户目标
  • 达到最大执行轮次
  • 工具连续失败
  • 需要用户补充信息
  • 命中高风险操作
  • 当前任务无法完成

停止条件不清晰，是 Agent 死循环的常见原因。

四、常见 Agent 类型

4.1 Tool-Using Agent

这是最常见的 Agent 类型，核心能力是根据任务选择工具。

适合：

  • 查订单
  • 查知识库
  • 调用业务系统
  • 生成结构化结果

4.2 Router Agent

Router Agent 负责把用户请求分发到不同链路。

例如：

  • 闲聊走普通问答
  • 公司制度问题走 RAG
  • 订单问题走数据库工具
  • 投诉问题创建工单

4.3 Planner-Executor Agent

这类 Agent 把规划和执行拆开：

  • Planner 负责拆任务
  • Executor 负责逐步执行

适合复杂、多步骤、可验证的任务。

4.4 Reviewer Agent

Reviewer Agent 负责检查输出质量或执行结果，例如：

  • 检查代码变更
  • 检查合同摘要
  • 检查答案是否引用证据
  • 检查工具参数是否合理

五、Agent 开发的关键难点

5.1 不确定性

模型输出有概率性，同样的问题可能产生不同的中间步骤。

工程上要用结构化输出、状态机、重试和校验来降低不确定性。

5.2 工具边界

工具设计太少，Agent 能力不足。

工具设计太宽，Agent 风险变高。

好的工具应该职责单一、参数明确、返回结构稳定。

5.3 可观测性

Agent 的每一步都应该能追踪：

  • 为什么调用这个工具
  • 工具参数是什么
  • 返回结果是什么
  • 下一步为什么这么选
  • 最终结果是否成功

没有 trace 的 Agent 很难上线维护。

六、常见误区

6.1 把 Agent 当成超级 Prompt

Prompt 很重要，但 Agent 的稳定性主要来自工具、状态、流程、评估和权限。

6.2 一开始就做 Multi-Agent

多数业务不需要一上来就多 Agent。单 Agent 加清晰工具和状态，通常更容易做稳定。

6.3 只看 Demo 效果

Demo 成功不代表生产可用。生产系统还要面对异常输入、权限限制、工具失败、并发、成本和审计。

八、常见面试题

8.1 AI Agent 和普通聊天机器人有什么区别？

普通聊天机器人主要完成“输入到输出”的回答，Agent 还会围绕目标选择步骤、调用工具、观察结果并更新状态。

8.2 AI Agent 和 RAG 是什么关系？

RAG 主要解决知识供给问题，Agent 主要解决任务执行问题。RAG 可以作为 Agent 的一个工具或知识层。

8.3 Agent 的核心组件有哪些？

通常包括 LLM、工具、状态、记忆、工作流、权限控制和可观测性系统。

8.4 为什么 Agent 需要状态管理？

因为 Agent 任务通常是多步骤的。状态用于记录已完成动作、工具结果、中间变量和等待事项，避免重复执行或丢失上下文。

8.5 为什么生产环境中的 Agent 不能完全自由行动？

因为它可能访问敏感数据、调用高风险工具或产生错误操作。生产环境需要权限、审批、审计、执行上限和降级策略。
