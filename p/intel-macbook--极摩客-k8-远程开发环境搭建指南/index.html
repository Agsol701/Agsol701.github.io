一、迷你主机网络配置

1.1 有线网络（推荐）

K8 和 MacBook 接入同一路由器/交换机，走有线获得最低延迟：

# 在 K8 上查看网口名称
ip link show

# 确认已获取 IP
ip addr show enp1s0   # 网口名称可能不同

# 设置静态 IP（避免 DHCP 变动）
sudo nmcli connection modify "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 192.168.1.100/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "223.5.5.5,8.8.8.8"

sudo nmcli connection up "Wired connection 1"

将 192.168.1.100 替换为你局域网中的可用 IP，网关和网段根据你的路由器调整。

1.3 ZeroTier 组网（跨网段/不同 VLAN 互通，推荐）

公司内网中 MacBook 和 K8 可能分配在不同子网/VLAN（如 MacBook 在 10.0.1.x，K8 在 10.0.2.x），直接 ping 不通。使用 ZeroTier 建立虚拟局域网可绕过网段限制。

第一步：创建 ZeroTier 网络

  1. 浏览器访问 https://my.zerotier.com
  2. 注册/登录账号（支持 Google/GitHub 登录）
  3. 点击「Create A Network」
  4. 记下生成的 16 位 Network ID（如 a1b2c3d4e5f6g7h8）

第二步：K8 上安装并加入 

1
2
3
4
5

curl -s https://install.zerotier.com | sudo bash
sudo zerotier-cli join 你的NetworkID

# 设置开机自启
sudo systemctl enable zerotier-one

第三步：MacBook 上安装并加入 

1
2

brew install --cask zerotier-one
sudo zerotier-cli join 你的NetworkID

安装后 macOS 菜单栏会出现 ZeroTier 图标，也可以通过图标加入网络。

第四步：授权设备（重要）

设备 join 后不会自动获得 IP，必须在管理面板手动授权：

  1. 回到 https://my.zerotier.com → 点击你的网络
  2. 下方 Members 列表中会出现两台设备（显示为 Member ID）
  3. 勾选每台设备前面的 Auth 复选框
  4. 授权后几秒内设备会自动获得 IP 地址（显示在 Managed IPs 列）
  5. 建议在 Name/Description 列填写备注（如 “MacBook”、“K8”）方便区分

注意：如果不勾选 Auth，设备虽然 join 了但无法通信，这是最常见的"连不上"原因。

第五步：验证连接 

1
2
3
4
5
6
7

# 两台设备上分别查看 ZeroTier 分配的 IP
sudo zerotier-cli listnetworks
# 输出类似：200 listnetworks <nwid> <name> <mac> <status> <type> <dev> <ips>
# 关注 status 应为 OK，ips 列显示分配的 IP（如 10.147.20.x）

# MacBook 上 ping K8 的 ZeroTier IP
ping 10.147.20.xx

之后所有 SSH、scp 等操作使用 ZeroTier 分配的 IP（10.x.x.x）即可。只要两台设备能上公网，无论在哪个网络都可以互通。

ZeroTier 管理面板说明

在 https://my.zerotier.com 的网络设置页面中：

区域 说明
Settings → Name 给网络起个名字（如 “my-dev-net”）
Settings → Access Control Private（需手动 Auth）/ Public（自动授权，不推荐）
Settings → IPv4 Auto-Assign 选择虚拟网段范围（默认 10.147.x.x/16，一般不用改）
Members 设备列表，Auth 授权、查看 IP、填备注
Flow Rules 网络流量规则（默认允许所有，一般不用改）

注意事项与常见问题

1. 设备 join 后 status 显示 ACCESS_DENIED

没有在管理面板勾选 Auth。去 Members 列表授权即可。

2. status 显示 REQUESTING_CONFIGURATION

网络 ID 输错了，或者网络已被删除。确认 Network ID 正确。

3. 两台设备 ping 不通

1
2
3
4
5
6
7

# 检查 ZeroTier 虚拟网卡是否 UP
ip link show | grep zt

# 检查防火墙是否拦截了 ZeroTier 网段
sudo ufw status
# 如果 ufw 开着，放行 ZeroTier 网段
sudo ufw allow in on zt+

4. 连接走中继（relay）导致延迟高

1
2

# 查看 peers，RELAY 表示走了中继，DIRECT 表示直连
sudo zerotier-cli listpeers

如果一直是 RELAY，说明两台设备之间无法打洞（公司防火墙限制 UDP）。解决方案：

  • 确保两端防火墙允许 UDP 9993 端口出站
  • 或自建 Moon 节点做中转（见下方）

5. 自建 Moon 节点加速（可选）

国内访问 ZeroTier 官方 Planet 节点较慢时，可在有公网 IP 的服务器上搭建 Moon：

# 在公网服务器上安装 ZeroTier
curl -s https://install.zerotier.com | sudo bash

# 生成 moon 配置
cd /var/lib/zerotier-one

sudo zerotier-cli orbit <moon-id> <moon-id>

6. 安全建议

  • 网络 Access Control 保持 Private（默认），避免陌生设备自动接入
  • 定期检查 Members 列表，移除不认识的设备
  • ZeroTier 免费版最多 25 个设备，个人使用足够
  • 如果离开公司网络后不需要连接，可以 sudo zerotier-cli leave <NetworkID>

2.2 MacBook 配置 SSH 免密登录 

1
2
3
4
5
6
7
8

# 生成密钥（如果还没有）
ssh-keygen -t ed25519 -C "your_email@example.com"

# 复制公钥到 K8
ssh-copy-id your_username@K8的IP

# 测试连接
ssh your_username@K8的IP

注意：ssh-copy-id 时使用的密钥必须和后面 config 中 IdentityFile 指定的一致。如果你有多个密钥（如 id_rsa、id_ed25519），用 -i 指定：

1

ssh-copy-id -i ~/.ssh/id_ed25519.pub your_username@K8的IP

2.3 配置 SSH 别名

编辑 ~/.ssh/config（MacBook 上）：

Host k8
    HostName 10.147.20.xx
    User your_username
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
    ServerAliveCountMax 3

各字段说明：

字段 含义
Host k8 自定义别名，之后 ssh k8 即可连接
HostName K8 的实际 IP（ZeroTier 分配的 IP）
User K8 上的登录用户名
Port SSH 端口，默认 22
IdentityFile MacBook 本机的私钥路径，用于免密认证
ServerAliveInterval 每 60 秒发心跳包，防止空闲断连
ServerAliveCountMax 连续 3 次心跳无响应才断开

配置保存后，ssh k8 等价于：

1

ssh -i ~/.ssh/id_ed25519 -p 22 your_username@10.147.20.xx

常见问题：配好了还是要输密码

原因 1：IdentityFile 路径不对

config 中指定的私钥文件必须实际存在：

1
2
3
4
5

# 查看本机有哪些密钥
ls ~/.ssh/id_*

# 确认 config 中写的路径和实际文件一致
grep IdentityFile ~/.ssh/config

如果密钥文件名不是默认的（如 id_rsa.myname），config 中必须写完整路径。

原因 2：公钥没传到 K8

1
2

# 重新传一次，用 -i 指定和 config 中一致的公钥
ssh-copy-id -i ~/.ssh/id_ed25519.pub your_username@K8的IP

原因 3：K8 上权限不对

SSH 对文件权限要求严格，在 K8 上执行：

1
2

chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

原因 4：IDE 频繁弹密码框

IDE（VS Code / Comate / Gateway）会开多条 SSH 连接，每条都要认证。添加多路复用可解决：

Host k8
    # ... 前面的配置 ...
    ControlMaster auto
    ControlPath ~/.ssh/sockets/%r@%h-%p
    ControlPersist 600

1

mkdir -p ~/.ssh/sockets

首次连接后，10 分钟内的后续连接复用同一通道，不再重复认证。

2.4 K8 上 SSH 安全加固（可选） 

1

sudo vim /etc/ssh/sshd_config

建议修改：

PermitRootLogin no
PasswordAuthentication no   # 仅允许密钥登录
MaxAuthTries 3

1

sudo systemctl restart ssh

四、MacBook 远程开发方式

4.1 VS Code Remote-SSH

最无缝的远程开发体验——代码在 K8 上，编辑器 UI 在 MacBook 上。

安装与配置

  1. MacBook 安装 VS Code
  2. 安装扩展：Remote - SSH（ms-vscode-remote.remote-ssh）
  3. 确保 ~/.ssh/config 已配置好 K8 连接（见第二节）

连接步骤

  1. Cmd+Shift+P → 输入 “Remote-SSH: Connect to Host”
  2. 选择 k8（或输入 agsol@K8的ZeroTier_IP）
  3. 首次连接会在 K8 上自动安装 VS Code Server（需等待 1-2 分钟）
  4. 连接成功后，左下角显示绿色 SSH: k8
  5. File → Open Folder → 选择 K8 上的项目目录（如 /home/agsol/workspace/my-project）

配置 Python 开发

  1. 在远程窗口安装扩展：Python（ms-python.python）
  2. Cmd+Shift+P → “Python: Select Interpreter”
  3. 选择项目的 .venv/bin/python 或 pyenv 的 Python 路径
  4. 终端中运行代码、调试断点，全部在 K8 上执行

配置 Go 开发

  1. 在远程窗口安装扩展：Go（golang.go）
  2. 连接后 VS Code 会提示安装 Go 工具（gopls、dlv 等），点 “Install All”
  3. settings.json 中确认 Go 路径：
1
2
3
4

{
    "go.goroot": "/usr/local/go",
    "go.gopath": "/home/agsol/go"
}
  1. F5 即可远程调试 Go 程序

推荐远程扩展

在 Remote-SSH 连接后安装（装在远程端）：

  • Python — Python 语言支持
  • Pylance — Python 智能补全
  • Go — Go 语言支持
  • GitLens — Git 增强
  • Error Lens — 行内错误显示

端口转发

VS Code 会自动检测 K8 上监听的端口并转发到本地。也可手动添加：

  • 点击底部面板 PORTS 标签
  • 点 Forward a Port → 输入端口号（如 8000）
  • 浏览器访问 localhost:8000 即可

4.2 PyCharm Remote（JetBrains Gateway）

方式 A：JetBrains Gateway（推荐）

代码完全在 K8 上，本地只运行 UI 客户端：

  1. MacBook 下载安装 JetBrains Gateway
  2. 打开 Gateway → 点击 SSH → New Connection
  3. 填写连接信息：
    • Host: K8 的 ZeroTier IP（如 10.147.20.xx）
    • Port: 22
    • Username: agsol
    • Authentication: Key pair → 选择 ~/.ssh/id_ed25519
  4. 点 Check Connection and Continue
  5. 选择 IDE：
    • Python 项目选 PyCharm Professional
    • Go 项目选 GoLand
  6. 设置项目目录：/home/agsol/workspace/my-project
  7. 点 Download and Start IDE
    • Gateway 会在 K8 上下载并安装 IDE 后端（首次约 5-10 分钟）
    • 后续连接几秒内打开

Gateway 中配置 Python 解释器

  1. IDE 打开后 → File → Settings → Project → Python Interpreter
  2. 点齿轮 → Add Interpreter → Add Local Interpreter（这里的"本地"指 K8）
  3. 选择 Virtualenv Environment → Existing → 路径填 /home/agsol/项目/.venv/bin/python

Gateway 中配置 Go SDK

  1. File → Settings → Go → GOROOT
  2. 设置为 /usr/local/go
  3. GOPATH 设置为 /home/agsol/go

方式 B：PyCharm Deployment + Remote Interpreter

适合习惯本地保留代码副本的工作流：

  1. 配置 SSH

    • File → Settings → Tools → SSH Configurations
    • 点 +：Host 填 K8 IP，Port 22，Username agsol，Auth type 选 Key pair
    • Test Connection 验证

  2. 配置 Deployment（自动同步）

    • File → Settings → Build, Execution, Deployment → Deployment
    • 点 + → 类型选 SFTP → 选择刚才的 SSH 配置
    • Root path：/home/agsol/workspace/my-project
    • Mappings 标签：Local path ↔ Deployment path 映射
    • Options：勾选 Upload changed files automatically to the default server → 选 On explicit save action (Ctrl+S)

  3. 配置远程解释器

    • File → Settings → Project → Python Interpreter
    • 点齿轮 → Add → On SSH
    • 选择 SSH 配置 → Interpreter path：/home/agsol/项目/.venv/bin/python
    • 同步文件夹映射确认后完成

  4. 运行/调试

    • 运行配置会自动使用远程解释器
    • 调试断点、变量查看全部在 K8 上执行

五、端口转发与服务访问

5.1 SSH 端口转发

在 K8 上运行的 Web 服务，通过 SSH 隧道在 MacBook 浏览器访问：

1
2
3
4
5

# 转发 K8 的 8000 端口到本地 8000
ssh -L 8000:localhost:8000 k8

# 多端口转发
ssh -L 8000:localhost:8000 -L 5432:localhost:5432 -L 3000:localhost:3000 k8

VS Code Remote-SSH 会自动检测并转发端口，无需手动配置。

5.2 持久化端口转发（可选）

在 ~/.ssh/config 中添加：

Host k8
    # ... 前面的配置 ...
    LocalForward 8000 localhost:8000
    LocalForward 3000 localhost:3000

  • SSH 密钥：不要在 K8 上存放 GitHub/GitLab 私钥，使用 SSH Agent Forwarding：
1
2
3

# MacBook ~/.ssh/config
Host k8
    ForwardAgent yes

这样在 K8 上 git push 时会使用 MacBook 上的密钥，无需在远程机器存私钥。
